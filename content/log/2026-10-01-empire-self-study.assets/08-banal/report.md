### Findings from source inspection

1. **The documentation promises more than it scopes.** The README lists “⌘⌫ — Move note to Trash”; the Help Book says the shortcut sends the file to Finder trash. Neither passage names a focus condition. Receipts: [README:49–60](https://github.com/drawmeanelephant/banal/blob/24e1da4439b016473119738b233eb8e636979cc6/README.md#L49-L60), [Help:34–36](https://github.com/drawmeanelephant/banal/blob/24e1da4439b016473119738b233eb8e636979cc6/Resources/BANAL.help/Contents/Resources/en.lproj/BANAL.html#L34-L36).
2. **The command exists; selection is not keyboard focus.** File → Move to Trash binds `.delete` + Command. It prefers `selectedID`, otherwise `selectedFolderPath`, and enables according to vault/selection, not first responder. Its model resolves `focused → tracked → fallback`, including a non-notes-window fallback. Receipts: [FileCommands:4–12,50–58](https://github.com/drawmeanelephant/banal/blob/24e1da4439b016473119738b233eb8e636979cc6/Sources/BANALApp/Commands/FileCommands.swift#L4-L58). `selectedFolderPath` derives from the filter; `listSelection` derives from `selectedID`: [AppModel:113–154](https://github.com/drawmeanelephant/banal/blob/24e1da4439b016473119738b233eb8e636979cc6/Sources/BANALApp/AppModel.swift#L113-L154). A policy based only on “a note is selected” cannot distinguish typing from filing.
3. **The editor delegates ordinary keys to AppKit.** `EditorTextView.keyDown` specially handles Escape and Tab, then calls `super`; no Command-Delete override was found. The text view enables undo. This supports a native text-command conflict as a hypothesis, not a reproduced event-dispatch diagnosis. Receipts: [MarkdownTextView:76–82](https://github.com/drawmeanelephant/banal/blob/24e1da4439b016473119738b233eb8e636979cc6/Sources/BANALApp/Views/MarkdownTextView.swift#L76-L82), [keyDown:562–596](https://github.com/drawmeanelephant/banal/blob/24e1da4439b016473119738b233eb8e636979cc6/Sources/BANALApp/Views/MarkdownTextView.swift#L562-L596).
4. **There is already a keyboard-only route out of prose.** ⌘2 focuses the note list; editor Escape also requests it, except that an open find bar gets native Escape handling. Context menus explicitly select the clicked note before trashing; folder context menus explicitly target the folder. Receipts: [ViewCommands:19–36](https://github.com/drawmeanelephant/banal/blob/24e1da4439b016473119738b233eb8e636979cc6/Sources/BANALApp/Commands/ViewCommands.swift#L19-L36), [EditorView:54–70](https://github.com/drawmeanelephant/banal/blob/24e1da4439b016473119738b233eb8e636979cc6/Sources/BANALApp/Views/EditorView.swift#L54-L70), [cancelOperation:550–559](https://github.com/drawmeanelephant/banal/blob/24e1da4439b016473119738b233eb8e636979cc6/Sources/BANALApp/Views/MarkdownTextView.swift#L550-L559), [NoteListView:25–33](https://github.com/drawmeanelephant/banal/blob/24e1da4439b016473119738b233eb8e636979cc6/Sources/BANALApp/Views/NoteListView.swift#L25-L33), [SidebarView:53–68](https://github.com/drawmeanelephant/banal/blob/24e1da4439b016473119738b233eb8e636979cc6/Sources/BANALApp/Views/SidebarView.swift#L53-L68). Their live effectiveness was not tested here.
5. **Trash is recoverable storage, not proven application undo.** Note trash calls `FileManager.trashItem`, removes the note, then chooses the first remaining visible note. These inspected paths register no undo action. `NoteStore.trash` cancels/removes pending writes before moving the on-disk file; latest-buffer recovery therefore needs explicit verification before making trash easier to trigger while typing. Folder trash, in contrast, calls `flush()` first. This is a source-backed recovery question, not a demonstrated loss reproduction. Receipts: [AppModel:301–309](https://github.com/drawmeanelephant/banal/blob/24e1da4439b016473119738b233eb8e636979cc6/Sources/BANALApp/AppModel.swift#L301-L309), [NoteStore:478–499](https://github.com/drawmeanelephant/banal/blob/24e1da4439b016473119738b233eb8e636979cc6/Sources/BANALCore/NoteStore.swift#L478-L499), [folder trash:312–330](https://github.com/drawmeanelephant/banal/blob/24e1da4439b016473119738b233eb8e636979cc6/Sources/BANALCore/NoteStore.swift#L312-L330).

### Recommendation, not owner decision

**Keep ⌘⌫ as a text edit in every editable text responder; use it for filesystem trash only in an explicitly focused note/folder collection.** Preserve explicit File/context-menu trash from the editor. Document ⌘2, then ⌘⌫ as the existing two-step filing route rather than silently promising one-step editor trash. If one-step editor trash is essential, let the owner choose a distinct shortcut after conflict checks; do not steal the native chord or add a preference by default.

This recommendation follows BANAL's own “Standard Mac text behavior” / native-control policy ([AGENTS.md](https://github.com/drawmeanelephant/banal/blob/24e1da4439b016473119738b233eb8e636979cc6/AGENTS.md)), not a claim that every Mac editor agrees. Bear documents note trash on this chord, IntelliJ documents whole-line deletion, and AppKit's local standard binding names deletion to line start. The survey explicitly records those differences.
